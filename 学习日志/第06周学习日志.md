# 第06周学习日志

2026年10月11日—10月17日

这周有一部分内容是在回头看变量，还有一部分开始把程序拆成函数。学到这里，我感觉基础知识之间的联系逐渐多了起来。一个表达式用什么类型计算，结果怎样交给函数，函数又怎样把结果交回来，都需要前后对应。代码虽然只多了几行，阅读时却不能只看某个孤立的语句。

类型别名让我认识到，有些写法主要是为了让代码更容易读。例如用 `using Score = double;` 给已有类型起一个名字，后面就能用 Score 表达成绩的含义。它仍然是 double 的别名，并没有凭空产生一种完全独立的新类型。这样的命名如果用得合适，可以让人更快看出一个变量准备保存什么。

`auto` 也让我觉得方便，但方便不代表可以忽略类型。写 `auto x = 5 / 2;` 时，前面的整数除法仍然得到整数，x 也不会因为使用 auto 就自动变成小数。读这种代码，我还是要先判断右边的表达式。至于 `decltype`，我目前把它理解为根据已有表达式取得类型，先认清用途，再慢慢熟悉更复杂的情况。

计算误差这一部分又提醒了我一次，小数运算不能完全照搬纸上的习惯。两个经过计算的小数，可能在很靠后的位置有差别。需要判断它们是否足够接近时，可以根据问题允许的误差比较差值，而不是处处直接使用相等判断。选择数据类型时，也要考虑数值可能有多大、需要保留多少精度，不能只图写起来省事。

函数是这一周最让我感到程序结构发生变化的内容。像求最大值、计算面积这样的工作，可以分别写成函数。函数名说明做什么，参数说明需要什么，返回值则交代计算结果。调用前需要有相应声明，定义里也要按照约定返回合适的内容。这样主函数可以先把整体步骤交代清楚，具体计算放在相应函数中。

我也开始注意参数和外部变量之间的关系。普通的值传递会把值交给形参，函数中改变这个形参，并不直接改变调用处原来的变量。理解这一点，才能继续看交换两个数为什么会有不同写法。课件还介绍了 inline，我先记住它和函数调用、编译处理有关，不能仅凭加上这个词就认定程序一定更快。对我来说，这周更重要的是把函数职责写清楚，让一段计算过程能够单独看懂。
