# 第10周学习日志

2026年11月8日—11月14日

这周围绕数据的共享与保护继续学习，我开始分清一些以前容易混在一起的问题。一个变量在某处能不能直接使用，和它保存的数据是否还存在，不能只看成同一件事。作用域主要帮助我判断名字在哪里可见，生存期则要看对象从什么时候建立、到什么时候结束。把这两个角度分开后，再看 static 就顺畅了一些。

普通局部变量在每次进入相应的执行过程时建立，离开时结束自己的生存期。局部静态变量则可以在多次调用之间保留数据。比如函数中有一个 `static int count = 0;`，每次调用都把它加一，就可以记录累计调用次数。虽然数据能够保留下来，但这个名字仍然受所在位置的作用域限制，不能因为它活得久，就认为程序各处都能直接使用它。

类中的静态数据成员，让我进一步理解了“共享”。如果每个 Point 对象都有自己的坐标，坐标应该跟随各个对象分别保存。如果要记录这类对象的某种总数，则可以考虑由一个静态成员统一保存。这样多个对象接触的是同一份计数数据。静态成员函数可以通过 `类名::函数名` 调用，读取这一类共享信息时，写法也比较清楚。

我也注意到，静态成员函数没有某个具体对象的 this 指针，因此不能像普通成员函数那样，直接使用某个对象的普通数据成员。假如要操作具体对象的信息，就需要有明确的对象来源。这个限制让我理解，static 并不只是“数据一直存在”的一个标记，还会影响函数与对象之间的关系。

友元提供了另一种访问数据的方式。一个函数得到某个类的 friend 声明后，可以访问该类允许友元访问的内部成员。不过这种许可需要明确写出，也不会因为双方“认识”就自动互相授权。我觉得这里最重要的是使用理由：如果普通成员函数和公开接口已经能把事情说明白，就先把这些方式用好，确实需要配合访问内部数据时再考虑友元。

const 则让我更认真地想一个操作是否需要修改数据。只负责显示或查询的成员函数，可以在声明后面加 const。常对象也需要通过合适的常成员函数来使用。把只读的意思写进函数中，后面读代码时就多了一条线索。这周我对类的理解比之前多了一层：除了把数据放进去，还要安排哪些数据各自保存、哪些需要共享，以及不同操作应该具有怎样的访问和修改权限。
