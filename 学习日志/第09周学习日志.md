# 第09周学习日志

2026年11月1日—11月7日

这周的内容比较零散，有结构体、联合体、枚举，也有类的补充知识和作用域。刚开始看时，我觉得像是在不断增加新的关键字。把它们放回具体用途之后，我发现它们解决的问题并不相同：有的帮助整理一组数据，有的让状态的名称更清楚，有的则决定一个名字在什么地方可以使用。

结构体是我比较容易接受的一部分。例如要保存一名学生的几项信息，可以把它们放在同一个 struct 里，再通过一个变量统一使用。C++ 的结构体中也能有成员函数。和 class 相比，一个需要记住的区别是，struct 的成员默认是 public，class 的成员默认是 private。选用哪种写法时，我会先看这个类型主要想表达什么，以及准备怎样使用它。

union 的特点让我意识到，外表上都写了好几个成员，实际存放方式却可能不同。联合体的成员共用一块存储空间，不能把它当成可以同时保存全部成员值的普通记录。读这类代码时，需要结合当前保存的是哪一种内容来理解。对于一般的学生信息，我仍然会先考虑结构体，不会为了少占一点空间就随便改成联合体。

枚举让我觉得程序中的状态更好读了。假如用数字 0、1、2 表示某种结果，过一段时间再看，可能要重新寻找每个数字的含义。给状态起明确的名称后，条件判断的意思就更直接。`enum class` 还要求通过类型名来访问枚举值，例如 `Result::Win`，不同类型中的同名取值也比较容易区分。我觉得这对菜单状态、星期和游戏结果都很有帮助。

类的补充部分介绍了 explicit 和对象传参。对于只读取一个对象信息的函数，使用 `const T&` 这样的参数，可以避免为传参再复制整个对象，同时限制通过这个参数修改对象。explicit 则让我知道，有些看似省事的自动转换可以受到限制。现阶段我先从例子的意图理解这些写法，不把每一种转换情况都硬记下来。

作用域这一部分把我带回了变量名。花括号里定义的局部变量，有自己能够使用的范围。如果内层和外层出现同名变量，直接写这个名字时，通常会先找到内层的那个。命名空间则帮助把不同地方的名称区分开，例如 `std::cout` 中的 std。以后读代码时，我会多问一句：这里用到的变量究竟是哪一个，它从哪里声明，又能在哪些位置使用。这比只盯着名字本身更可靠。
